# Эпоха 12 — Валидатор и машинный протокол

## Цель

Не валить перевод, где модель сознательно оставила машинную тарабарщину (`HOSTILE by%?`, `a_start`, `redo from start` среди `0110…`). Целая непереведённая проза (`the blade and the war`) по-прежнему fail.

## Вход / выход

**Вход:** тот же `ITranslationValidator.Validate(source, response)`.

**Выход:** `ValidationResult`. При fail из-за стоп-листа в `Reason` — конкретное слово (`English function word: from`).

## В скоупе

- Только [`TranslationValidator`](../../src/Ai.Translator.Core/Translation/TranslationValidator.cs). Пайплайн, ретраи, `--resume` Failed, бар, эпоха 11 — не трогать.
- Токен служебного слова — целый идентификатор `[A-Za-z][A-Za-z0-9_]*`. `a_start` не даёт `a`.
- Строки/текст после среза HTML с «протокольным» видом не сканировать на стоп-лист: длинный двоичный прогон (`[01]{8,}`), высокая доля цифр, каша `=` / `%` / `/` рядом с цифрами.
- Не разрешать слово «если оно было в source» — source всегда английский.
- Стоп-лист тот же, что в 03. Имена (`Eisenhorn`) не служебные слова.

## Вне скоупа

- переигрывать `Failed` при `--resume`
- показывать ретраи 2/3 в баре
- живой бар (эпоха 11)
- файл стоимости

## Контракты

```
ITranslationValidator.Validate(sourceChunk, LlmResponse) -> ValidationResult
ValidationResult.Reason  // при стоп-листе: "English function word: {token}"
```

## Критерии приёмки

- `<p>the blade and the war</p>` — fail, Reason содержит `the` (или другое слово стоп-листа)
- `<p>Eisenhorn прибыл</p>` — pass
- HTML с `HOSTILE by%?`, `a_start=678ren`, `redo from start` и двоичными прогонами `0110…` — pass
- смесь: одна протокольная строка и отдельный `<p>the blade and the war</p>` — fail
- тесты не ходят в сеть

## Риски

- Слишком широкий «протокол» — пропустить недоперевод с годом в тексте. Порог: двоичный прогон 8+ или цифр не меньше букв половины и не меньше 6 штук.
- `` .NET считает `_` словом — не резать `[A-Za-z]+` на `_`.
