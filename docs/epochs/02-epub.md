# Эпоха 02 — EPUB

## Цель

Читать книгу по spine и писать перевод обратно так, чтобы оглавление, CSS, картинки и метаданные остались родными. Выход — тот же EPUB, не «txt в обложке».

## Вход / выход

**Вход:** валидный EPUB 2/3.

**Выход:**

- список глав reading order: путь entry в ZIP, исходный XHTML, plain text, пригодный к нарезке список блочных фрагментов
- операция «заменить тело выбранных XHTML и сохранить как новый файл»
- исходный файл не модифицируется

## В скоупе

- `IEpubBookService` (один порт, без зоопарка reader/writer, если не нужно)
- чтение через `VersOne.Epub`
- запись: `File.Copy` + `ZipArchiveMode.Update`, заменить только указанные entry
- нормализация пути entry (`\` vs `/`)
- разбор XHTML через HtmlAgilityPack: `html/head` не переводить, работать с содержимым `body`
- блочные узлы для будущей нарезки: `p`, `h1`–`h6`, `blockquote`, `li` как минимум
- сохранять inline-разметку (`i`, `em`, `b`, `strong`, `span`) внутри блока
- пропуск пустых spine-элементов без текста
- unit-тест на минимальном валидном EPUB, собранном в тесте (mimetype, container.xml, OPF, одна глава, картинка или CSS)

`glossary compile` переводится на этот порт, временный extractor из эпохи 01 удаляется.

## Вне скоупа

- PDF
- перевод текста
- починка кривых EPUB издательства
- генерация нового TOC
- смена метаданных (язык выходной книги можно выставить в эпоху 03, не здесь обязательно)
- DRM, epubcheck как обязательный шаг CI

## Контракты

Имена ориентир:

```
EpubChapter
  FilePath          // имя entry в архиве
  Xhtml
  PlainText
  BodyInnerHtml

EpubReplace
  FilePath
  BodyInnerHtml     // уже переведённый или исходный

IEpubBookService
  OpenAsync(path, ct) -> EpubBookModel
  WriteCopyAsync(sourcePath, destinationPath, replacements, ct)
```

Не читать книгу в CLI напрямую через VersOne.

## Критерии приёмки

- тест: копия EPUB открывается VersOne после replace; картинка/CSS entry на месте; текст главы заменён
- `mimetype` остаётся первым stored-entry либо книга всё ещё открывается читалкой/VersOne (не пересобирать архив с нуля)
- главы с курсивом отдают HTML, где `<em>`/`<i>` не выкинуты в PlainText-only API для переводчика — переводчику нужен HTML фрагмент
- PDF по-прежнему отвергается на CLI, не в этом сервисе

## Риски

- `CreateEntry` после `Delete` может переставить файл в конец архива — для XHTML это допустимо, для `mimetype` нет. `mimetype` не трогать.
- Перекодировка в UTF-16 / BOM сломает часть читалок — писать UTF-8 без BOM.
- Два независимых способа достать текст (regex vs HAP) разъедут compile и translate. Один разбор.
- EpubSharp «очистить главы и добавить заново» потеряет CSS/навигацию — не использовать.
