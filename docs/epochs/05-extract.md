# Эпоха 05 — Extract

## Цель

Режим наполнения словаря: из пары «оригинал + уже существующий литературный перевод» модель предлагает записи в полный корпус. Человек ревьюит. Вики и форумы сюда не входят.

## Вход / выход

**Вход:**

- EPUB оригинала
- EPUB перевода того же произведения (желательно то же издание/нарезка, гарантий нет)
- опционально уже существующий корпус MD для слияния

**Выход:**

- MD с предложенными записями в каноническом формате
- при `--merge-into` существующего корпуса: новый файл или in-place по флагу, без затирания канонического `ru`
- человек всё ещё обязан открыть файл глазами

## В скоупе

- `glossary extract` перестаёт быть заглушкой
- выравнивание «по индексу spine»: глава i оригинала + глава i перевода. Если длины reading order разные — предупреждение и пары до min(len); хвост в лог
- модель в роли экстрактора, не переводчика: другой prefix (правила извлечения + уже известные термины корпуса, чтобы меньше дублировать)
- ответ модели — Markdown записей; парсер эпохи 01 должен его прочитать (допустим окружающий текст: брать с первого `##`)
- слияние по правилам [glossary-format.md](../glossary-format.md): существующий `ru` священен
- батчи по главам/кускам с тем же `ILlmProvider` (StablePrefix = инструкции extract + текущий корпус или его сжатый перечень English, VariableContent = пара текстов)
- если корпус слишком большой для prefix — в prefix только список уже известных English (без notes), полные записи не обязательны
- unit-тесты слияния и «не затереть ru»; мок LLM на одну пару глав

Человек в цикле обязателен продуктово: CLI не публикует словарь в translate автоматически.

## Вне скоупа

- парсинг fandom / warforge
- автоматическое принятие кандидатов из эпохи 03
- sentence alignment, hunalign, BERT-align
- OCR
- разрешение конфликтов изданий моделью «голосованием»
- запись EPUB

## Контракты

```
ai-translator glossary extract --original <epub> --translation <epub> --out <md>
    [--merge-into <corpus.md>]
    [--model <id>]
```

```
IGlossaryExtractor.ExtractAsync(original, translation, existingCorpusOrNull, ct) -> GlossaryDocument
```

Слияние можно вынести в `IGlossaryMerger`, чтобы тестировать без LLM.

Prefix extract не обязан совпадать с prefix перевода. Кеш extract менее критичен: прогон редкий. Всё равно не собирать уникальный «словарь главы» в prefix, если можно держать список известных English стабильным на книгу.

## Критерии приёмки

- мок, вернувший две `##` записи, даёт валидный MD на диске
- merge: старый `ru` жив, новый alias дописан, новая статья добавлена в конец
- разные длины spine не падают исключением без сообщения
- PDF отвергается тем же правилом, что в 00
- translate не вызывается из extract и наоборот

## Риски

- Считать выравнивание по индексу истиной: предисловия/выходные данные съезжают. Для v1 это приемлемо, в логе писать названия/пути глав пары.
- Кормить в модель всю книгу одним запросом — запрещено, те же бюджеты окна.
- Подмешивать extract-выход в рабочий словарь перевода без compile и без глаз — запрещено.
- Этот режим легко превратить в «переведи и заодно собери словарь» — не делать. Другой system prompt.

## Зависимости

Эпохи 00–04 (нужны EPUB, парсер MD, провайдеры). Без 04 extract не ходит в сеть «напрямую» из команды.
